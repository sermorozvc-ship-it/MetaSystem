# Формат файлов программ тренировок (week-*.md)

Эти правила обязательны при генерации, редактировании и сохранении файлов
программ тренировок (недельных дневников). Их нарушение ломает интеграцию
с внешней моделью, которая анализирует прогресс по факту подходов.

## Главное правило: YAML frontmatter неприкосновенен

В начале каждого файла программы есть YAML frontmatter — первые ~9 строк,
обрамлённые `---`. Внешняя нейронка использует этот блок как первичный
источник метаданных (неделя, клиент, контекст программы).

**Что должно соблюдаться:**

1. **Не трогать frontmatter при заполнении факта подходов.** Когда клиент
   или приложение вписывают фактические веса/повторы — изменяется только
   тело документа, frontmatter остаётся байт-в-байт тем же.
2. **Возвращать файл с теми же первыми 9 строками, что были получены.**
   Любая операция чтение → запись должна сохранять frontmatter без
   модификаций (включая порядок ключей, кавычки, пустые строки, пробелы).
3. **Никогда не вырезать frontmatter** — даже «для красоты» при экспорте,
   нормализации или санитайзе markdown. Если frontmatter пропадёт,
   нейронка перейдёт на резервные уровни (имя файла, контекст разговора),
   и точность анализа упадёт.

## Что считается «не трогать»

- Не переформатировать YAML (отступы, кавычки, регистр ключей).
- Не сортировать ключи.
- Не дописывать в frontmatter автоматические поля (updated_at и т.п.) без
  явного запроса — это меняет первые 9 строк.
- Не переводить значения (если в исходнике `goal: hypertrophy`, не менять
  на `goal: гипертрофия`).
- Не добавлять/удалять пустые строки до или после блока `---`.

## Безопасный паттерн обработки

При любой операции вида «прочитать файл недели → внести изменения → сохранить»:

```ts
// 1. Разделяем frontmatter и тело по первому закрывающему '---'
const match = content.match(/^(---\r?\n[\s\S]*?\r?\n---\r?\n)([\s\S]*)$/)
if (!match) {
  // frontmatter отсутствует — работаем как с обычным markdown,
  // но логируем предупреждение: упадём на резервный уровень анализа
  console.warn('[training] week file without frontmatter')
}
const [, frontmatter, bodyRaw] = match ?? ['', '', content]

// 2. Все правки делаем ТОЛЬКО в bodyRaw
const newBody = applyFactSets(bodyRaw, fact)

// 3. Склеиваем обратно — frontmatter возвращаем как есть
const result = frontmatter + newBody
```

Не использовать YAML-парсеры с обратной сериализацией (`js-yaml.dump`,
`gray-matter` со stringify) для записи — они переформатируют блок.
Только парсить для чтения, а при записи склеивать исходную строку.

## Резервные уровни (на случай если frontmatter всё-таки потерян)

Внешняя модель в этом порядке деградирует:

1. **frontmatter** — основной источник (точно).
2. **имя файла** — `week-1-filled.md`, `week-3.md` и т.п.
3. **контекст разговора / соседние файлы** — наименее точно.

Это значит: даже если что-то сломалось, система не падает, но точность
советов по прогрессу снижается. Цель — держаться на уровне 1.

## Чек-лист перед коммитом изменений в логику программ

- [ ] Чтение файла не нормализует frontmatter.
- [ ] Запись файла склеивает исходный frontmatter + новое тело.
- [ ] Тесты/ручная проверка: первые 9 строк до и после операции идентичны
      (diff пустой по этой части).
- [ ] Если frontmatter отсутствует во входе — он не «достраивается»
      автоматически, файл сохраняется как есть с предупреждением в логах.
